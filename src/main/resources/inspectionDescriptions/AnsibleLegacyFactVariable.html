Reports a gathered fact used as a top-level variable, such as ansible_os_family, ansible_distribution or ansible_default_ipv4, in an Ansible playbook, role or variables file.

ansible-core 2.20 deprecates injecting facts as top-level variables: INJECT_FACTS_AS_VARS still defaults to True in 2.20 but defaults to False in 2.24, after which only ansible_facts['os_family'] (or ansible_facts.os_family) keeps working. The quick fix rewrites the variable to the ansible_facts form, which works in every supported version.

Only names that are gathered facts are reported. Connection settings and magic variables (ansible_host, ansible_user, ansible_connection, ansible_python_interpreter, ansible_check_mode, ansible_version, ansible_play_hosts, ...) keep working and are never reported. Checked inside {{ }} and {% %}, and in the value of when, failed_when, changed_when, until and that; text inside quoted strings in an expression, and variables reached through another object (hostvars[h].ansible_os_family), are left alone.
